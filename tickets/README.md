# Work records

This directory records planned changes, task status and implementation evidence. Development tickets and coordination records do not override the [current MVP specification](../docs/mvp-spec.md).

## Record types

- A **development ticket** is a small implementable task named `# Ticket DEVNNNN` with a `DEVNNNN-short-title.md` filename. It owns implementation and validation evidence, and its DEV ID is used in commits. Start one from [TEMPLATE.md](TEMPLATE.md).
- A **coordination record** is a non-implementation umbrella named `# Coordination CORNNNN` with a `CORNNNN-short-title.md` filename. It maps a flat set of peer development tickets and is never used as a commit reference. Start one from [COORDINATION_TEMPLATE.md](COORDINATION_TEMPLATE.md).

DEV and COR have independent four-digit sequences. Allocate the next unused number within the relevant prefix after checking current, archived and retired records. The next available IDs are DEV0043 and COR0003.

Every DEV record declares its direct coordination membership near the top: one linked COR, or `None — independent development ticket`. Direct membership is limited to one COR and must match that COR's work map. Dependencies, downstream consumers and historical links remain separate relationships.

Use at most one coordination-to-development level by default. When pre-implementation review splits a proposed DEV into several implementation tickets, convert its planning record to the next COR ID, retire the former DEV ID and create fresh peer DEV records linked to that COR. Preserve a DEV that already has implementation or commit history and create a separate COR instead. Avoid child-of-child ticket trees.
